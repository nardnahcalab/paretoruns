Key finding: At c1-c4, p99 latency stays under 5s. Beyond c8, p99 exceeds 6s. For a <2s p99 SLO, the system is limited to c1 (98 tok/s). For a <4s SLO, c4 works (193 tok/s). The tradeoff is clear: more concurrency = more throughput but worse tail latency.

Summary: Memory is the binding constraint for 10K-user deployment, not throughput. The GB10 can handle ~5 concurrent 128-tok requests or ~1 concurrent 512-tok requests before hitting GPU compute limits. But the 256K context memory limit (27 sessions) is reached first. Optimizing the scheduler or reducing context length would have more impact than adding GPU compute.

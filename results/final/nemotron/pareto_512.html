4. Analysis

128 vs 512 Token Comparison

Nemotron maintains its 2x advantage at 512 tokens. At c1, 128-token decode is 112 tok/s and 512-token is 99.5 tok/s — a 12% reduction (vs Qwen's 0% reduction). This slight degradation is because the longer input sequences (ISL ~1000 vs ~300) consume more Mamba state, but the effect is modest.

Scaling Behavior

Throughput scales 3x from c1 to c8 (0.18 → 0.54 req/s). The scaling exponent is 0.60 — slightly higher than 128-token (0.54), meaning longer outputs benefit more from batching. This is because the fixed overhead (TTFT, scheduling) is amortized over more tokens.

Capacity Planning for Long Outputs

512-token serving: At c8, Nemotron serves 0.54 req/s per GB10. For 10K concurrent users generating 512 tokens, you need ~18,519 GB10 nodes (vs ~1,877 for 128-token). The 4.2x increase in E2E latency directly translates to proportionally more nodes needed.

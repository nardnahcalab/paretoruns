Optimization levers to reduce GPU count:
  1. Prefix caching: If 4K system prompt is cached, saves ~13MB per session. At 10K users, saves ~125 GiB total.
  2. Shorter context: At 64K context, 27 sessions/GPU — need only 370 GPUs.
  3. Mamba advantage: Pure MoE at 256K would need O(n^2) attention memory. Mamba's constant memory is why this is feasible at all.
  4. Multi-GPU EP: Expert Parallelism across 4-8 GB10s with NVLink would reduce per-GPU memory pressure.

D2: Routing Stability at Long Context

Hypothesis: Does routing entropy change at extreme context lengths (64K-256K)? Mamba layers process all tokens with constant memory, so long-context inputs should not destabilize MoE routing decisions.

Result: Latency scales sublinearly with context length (scaling exponent ~0.19). Routing behavior remains stable across all context lengths tested. The Mamba layers' constant-memory processing ensures that long contexts do not degrade MoE routing quality. This confirms that the hybrid architecture's routing is content-aware, not context-length-dependent.

4. Analysis

128 vs 512 Token Comparison

Decode speed is output-length invariant. At c1, 128-token decode is 22.7 tok/s and 512-token is 22.8 tok/s — identical. This confirms that each token generation step takes the same time regardless of how many tokens have been generated. The difference is in total latency: 512-token takes 5x longer (23s vs 5.9s) because there are 5x more tokens to generate.

TTFT Scaling

TTFT is 1.6x higher at 512-token (290 ms vs 184 ms). This is because the input prompts are longer (ISL ~1000 vs ~300 tokens) — the prefill phase processes more input tokens before starting decode.

Why Random Failed at c2+

Random word sequences produce tokens that are harder for the tokenizer and model to process efficiently. At 512 tokens, the cumulative ITL grows to the point where the request times out before completing. This is a model-specific issue with random token generation.

Capacity Planning for Long Outputs

512-token serving requires 3.9x more GPU time per request. For the same throughput, you need 3.9x more concurrency or 3.9x more GPUs. At c8, GB10 serves 0.28 req/s for 512-token output vs 1.11 req/s for 128-token — a 4x reduction in capacity.

MoE Routing Probe Analysis

Qwen3.6-35B-A3B NVFP4 on NVIDIA GB10 — How does the router distribute tokens across 256 experts?

Questions We Want to Answer

  1. How evenly does the router distribute tokens across experts? — Is load balanced, or do hot experts emerge?
  2. Does input content change routing behavior? — Do text, random, reasoning, and repetitive inputs use different experts?
  3. How does vocabulary diversity affect routing? — What happens when all words are replaced with "hi"?
  4. Does routing change across layers? — Do early vs deep layers route differently?
  5. Does routing change with sequence position? — Early vs mid vs late tokens in a sequence?
  6. What are the implications for multi-GPU Expert Parallelism? — How does load imbalance affect GB10 vs XE9780 with 8×B300?
Why these questions matter: Mixture-of-Experts models only activate a fraction of parameters per token. Understanding routing is critical for infrastructure planning, load balancing, and cost optimization at scale.

Dataset Design

Four datasets engineered to isolate specific routing variables

TEXT — Natural Language Baseline

"How can I improve my sleep quality?"

Control: tests routing without meaning

REASONING — Chain-of-Thought

200 sessions · ~200+ reasoning tokens · 1-6 turn depth

"Explain why correlation does not imply causation"

Tests whether logic changes routing

HI-REPEATED — Zero Vocabulary Diversity

500 sessions · 1 unique word · 1-10 turn depth

"hi hi hi hi hi hi hi hi hi hi"

Isolates vocabulary diversity as a variable

Key insight: Text and hi-repeated have identical structure (500 sessions, same turn distribution). Only word content differs. This 134x vocabulary difference drives a 30.9% entropy reduction in routing.

Why This Matters for MoE

  • Expert weights (~4 MB each in NVFP4) must load from HBM → SRAM before compute
  • SRAM is only ~40 MB — cannot hold all 256 experts
  • Top-8 routing: 8 experts × 4 MB = 32 MB per layer (fits in SRAM)
  • Bottleneck is HBM → SRAM transfer at 8 TB/s

Prefill parallelism: All input tokens are processed simultaneously. The router assigns each token to its own expert subset. This is compute-bound — experts process token batches efficiently.

Decode: Generate One Token at a Time

Each new output token triggers a full forward pass through all 40 MoE layers. The router picks experts for this token only.

Step 1
Last generated token: "quality"
Step 2
Router selects: E12, E45, E87, E92, E103, E156, E201, E245
Step 3
8 experts compute, outputs weighted → next token logits
Repeat
Next token: "?" → new routing decision → new 8 experts

Each decode step = 1 token → 40 MoE layers → 80 all-to-all collectives (in EP). Routing decisions change per token.

Decode is memory-bound: Each token requires loading expert weights from HBM. The KV cache grows with each token. Hot experts create bottlenecks — all GPUs wait for the busiest one.

Why Entropy Is Similar Across Content Types

  1. Training regularization — auxiliary loss pushes ALL distributions toward same shape
  2. Top-8 structural constraint — 3.1% utilization limits how different entropy can be
  3. Short decode sequences — 8 tokens barely starts generation
  4. Router is content-agnostic in diversity — optimizes for balance, not content-dependent spread

NVFP4 Quantization Impact

  • 4-bit precision reduces memory 4x vs bf16
  • Router gate uses 4-bit activations (minor quantization noise)
  • Entropy patterns stable across datasets (0.76-0.85)
  • Router is robust to precision loss
  • NVFP4 routing comparable to FP8 models

Key Findings

  1. Content-agnostic routing diversity: Text, random, and reasoning produce similar entropy (0.76-0.79) but route to different experts (Jaccard 0.11)
  2. Vocabulary diversity is critical: Replacing all words with "hi" reduces entropy by 30.9%, creating hotspot experts
  3. Layer variation is severe: Entropy varies 0.70-0.86 across layers; EP must provision for worst-case (layer 30: 22.9x imbalance)
  4. Position effect is universal: Entropy increases 6-12% from early to late positions in all datasets

Recommendations

  1. For GB10: Load imbalance is manageable (SRAM-bound, ~30-50% perf loss)
  2. For XE9780 + 8×B300: Load imbalance is critical (communication-bound, 2-5x perf loss). Use expert replication and dynamic load balancing
  3. For repetitive workloads: Provision for 35x imbalance. Consider input preprocessing to diversify prompts
  4. For monitoring: Track Jaccard/Cosine, not just entropy. Entropy alone misses content-dependent routing
Bottom line: The Qwen NVFP4 router is content-aware (routes differently for different content) but content-agnostic in diversity (similar distribution shape). Vocabulary repetition is the primary risk factor for load imbalance. For multi-GPU deployments, always provision for worst-case layers and repetitive input patterns.

Power & Routing Correlation

Workload-Independent Power

  • GPU draws 33-34W sustained regardless of dataset — power is dominated by memory subsystem, not compute
  • GB10 power range: 14W (idle) → 67W (peak), sustained ~34W during inference
  • Temperature: 63-69°C under load

Active Experts Drive Efficiency

  • Random: 188 active experts → best efficiency (4.33 tok/s/W, 231 mJ/tok)
  • Text: 164 active experts → middle (4.02 tok/s/W, 249 mJ/tok)
  • Reasoning: 158 active experts → worst (3.98 tok/s/W, 251 mJ/tok, 74.6% GPU util)
  • Hi-repeated: only 36 active experts — would be least efficient (68.8% concentration in top-8)
  • More active experts = better GPU SM utilization = higher tok/s/W
